# 學習功能嚴重缺損課程調整與教學設計｜期末成果逐組互評

**版本：SF-2026-v1.0｜2026 年秋季｜GitHub Pages 單頁 + Google Apps Script + Google Sheet**

本系統保留「教學原理互評」原版的深藍色頁首、白色卡片、學號姓名登入、週次切換與唯讀心得紀錄，但本門課的評分改成：**當週每一組都評「好玩」「好用」「好學」，每項 1–4 分，並各寫至少 10 字心得**。

學生只使用 GitHub Pages 的 `index.html`，填學號、姓名後直接在**同一個頁面**評分，沒有整頁 iframe、不會跳到 Google Apps Script 或 Google Drive，也不需要建立 `Vote.html`。

## 請先注意：這是一門不同的課

**請使用新的 Google Sheet、綁定這份 Sheet 的新 Apps Script 專案、以及新 GitHub 儲存庫。**

- **不要**把本包的 `Code.gs` 貼到「教學原理」的 Apps Script 中，否則舊課程可能失效。
- **不要**沿用「教學原理」的 `/exec` 網址：那個網址會指向不同的資料服務。
- 本包前端的 `WEB_APP_URL` 暫時是明確的佔位文字，因為只有你建立新部署後才會有新的真正網址；**不能將尚未連線的頁面當成已可正式收件**。
- Google Sheet 中的 38 位同學已經直接寫在**新課的後端 `Code.gs`**。`setup()` 自動建立正式名單，毋須手動匯入 CSV。

## 只需要兩個主要檔案

| 檔名 | 放的位置 | 用途 |
|---|---|---|
| `Code.gs` | **新的 Google Sheet → 擴充功能 → Apps Script** | 核對學號、姓名、日期、報告組別，收取評分及心得，保存至 Sheet |
| `index.html` | **新的 GitHub repository 根目錄** | 學生手機及電腦看到的單頁網站 |

另附 `期末互評學生名單_38人.xlsx`、`學生名單_38人.csv` 供教師留存核對，不需要貼到網站。

## 設定步驟

1. **建立新的 Google 試算表。** 例如「115-1 學習功能嚴重缺損課程調整與教學設計｜互評紀錄」。
2. 在該 Sheet 選「**擴充功能 → Apps Script**」。開啟原本的 `程式碼.gs`，把內容換成本包的 **`Code.gs` 完整內容**並儲存。
3. 在函式選單選 **`setup` → 執行**，授權存取這份試算表。再選 **`checkSetup` → 執行**，執行結果應確認「**38 人／10 組／4 週**」。這時 Sheet 會出現：
   - `重損_正式名單`（學號、姓名、分組、報告日）
   - `重損_互評回覆`（每評一組一列：三項分數、滿分 12 分、10 字以上心得）
   - `重損_統計總覽`（各組有效筆數、三項平均、總分平均、完成率）
4. 右上角 **部署 → 新增部署 → 網頁應用程式**。執行身分選「**我**」，誰可以存取選「**任何人**」，再按「部署」。複製得到的新 `https://script.google.com/macros/s/.../exec` 網址。
5. 在 `index.html` 搜尋這一行：

   ```javascript
   const WEB_APP_URL = 'PASTE_NEW_COURSE_APPS_SCRIPT_EXEC_URL_HERE';
   ```

   把引號內的文字換成**這門課新部署**的完整 `/exec` 網址；不要使用另一門課的網址。
6. 建立新的 GitHub repository（名稱可用 `115-1-sf-peerreview`），上傳**已填好新 `/exec` 網址**的 `index.html` 到根目錄。到 Settings → Pages → Deploy from a branch，選 `main` / `(root)`，儲存。
7. 讓同學開 GitHub Pages 網址，會直接看到學號、姓名與原版風格的互評頁。**不需要學生開 Apps Script 網址**。

### 上線前的兩階段確認

**第一階段：確認後端已啟動。** 直接用瀏覽器開啟新 `/exec`，應看到純文字：

> 重損課程成果互評資料接收端 SF-2026-v1.0 已啟用；學生請從 GitHub 網頁填答。

**第二階段：確認實際收件。** 使用新 GitHub Pages 網址，請一位本週非報告組員先正常填寫一組，確認 Sheet `重損_互評回覆` 多出一列，三項評分與心得正確，再讓全班使用。**不要用同學名義測試送出**，因為每個人每組只可填一次。

如果更新後端程式，必須到 **部署 → 管理部署 → 編輯舊部署 → 版本選「新版本」 → 部署**。只按程式的「儲存」並不會更新 `/exec` 所使用的已發布版本。

### 評分規則

- **好玩：** 1～4 分，著重活動吸引力、參與感。
- **好用：** 1～4 分，著重教材教具或策略的實用程度。
- **好學：** 1～4 分，著重說明清楚、學習與操作的容易程度。
- **心得：** 每一組至少 10 字（空格、換行不計），**可以超過 10 字**。
- 一組的三項評分合計 **3～12 分，滿分 12 分**。各組可個別送出，不必等全部寫完才提交。
- 伺服器會核對學號、姓名、當週免評、開放日與重複紀錄；**每名學生對每個組別只可送一次，送出後不能修改**。
- 下週同樣輸入學號與姓名，可回顧已提交的所有組別分數及心得，仍為唯讀。

## 哪些資料會公開？

- `index.html` 公開的是組別與日期，不包含全班學號姓名。
- `Code.gs` 放在教師的 Google 帳號裡，包含 38 位學生名單；不要把 `Code.gs` 發布到公開的 GitHub repository。
- 只有公開的資料接收端能接收評分，Sheet 本身不需要公開共用權限。
- **學號＋姓名只算簡易辨識，不是安全的個人驗證。** 如果知道別人的學號與姓名，就可能冒名查詢；如果用於正式成績，建議進一步使用學校帳號登入或個別驗證碼。
- 用戶端不會把學號、姓名或心得放在 GET URL；後端短時效查詢只使用隨機 token。此方案沿用 Google Apps Script ContentService 的資料服務及 JSONP 回覆方式（官方文件：<https://developers.google.com/apps-script/guides/content>）。

## 疑難排解

- **看到「此課程尚未設定獨立的 Google Sheet 接收網址」：** 這表示 `index.html` 還沒有放入新課的 `/exec`，不是學生網路問題。
- **看到「後端版本不符合本課程」：** 可能貼錯成「教學原理」的部署網址，或 Apps Script 忘記建立／更新「新版本」。
- **可以進首頁但查詢超時：** 打開新的 `/exec` 確認會顯示 SF-2026-v1.0 字樣；並確認部署以教師身分執行、允許「任何人」存取。
- **姓名學號找不到：** 核對名單是否正確；新後端已包含 38 人，無須學生自行登記。
- **送出後不確定是否成功：** 留在同一個頁面，使用相同提交編號「重新確認這組是否已送出」，避免重複寫入。
